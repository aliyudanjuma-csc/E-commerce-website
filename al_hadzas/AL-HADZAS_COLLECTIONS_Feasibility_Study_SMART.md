## 1. Purpose

This feasibility study assesses whether AL-HADZAS COLLECTIONS — a global e-commerce platform for authentic traditional African attire — is viable to design, build, and launch as a coursework project (with a realistic path to a real-world MVP). Each feasibility dimension is expressed as a **SMART objective** (Specific, Measurable, Achievable, Relevant, Time-bound) so that success or failure can be judged objectively rather than subjectively.

The study covers five standard feasibility dimensions:
1. Technical Feasibility
2. Operational Feasibility
3. Economic/Financial Feasibility
4. Legal & Regulatory Feasibility
5. Schedule Feasibility

---

## 2. Technical Feasibility

**Question:** Can the required system realistically be built with available skills, tools, and infrastructure?

| SMART Element | Detail |
|---|---|
| **Specific** | Build a multi-vendor e-commerce web platform with authentication, product catalogue, cart/checkout, vendor dashboard, and admin moderation, using a standard stack (e.g., React/Next.js frontend, Node.js/Django backend, PostgreSQL, Stripe/Paystack sandbox for payments). |
| **Measurable** | All 8 MVP features listed in the Idea & Validation report are functional and demoable; checkout completes end-to-end in sandbox mode with zero critical bugs. |
| **Achievable** | The stack uses widely documented, free/open-source tools already covered in a standard CS curriculum; no proprietary or exotic infrastructure required. |
| **Relevant** | Directly satisfies the coursework requirement to design and implement a working e-commerce website. |
| **Time-bound** | Core MVP (catalogue, cart, checkout, vendor dashboard) functional within 6–8 weeks, leaving 2–3 weeks for testing and polish before submission. |

**Verdict: Feasible.** No component requires technology beyond a graduate CS student's reach; risk is schedule discipline, not technical capability.

## 3. Operational Feasibility

**Question:** Can the business actually run day-to-day — will vendors list products and will buyers use the platform as intended?

| SMART Element | Detail |
|---|---|
| **Specific** | Onboard a pilot group of African tailors/designers as vendors and simulate real buyer journeys (browse → size guide → checkout → mock order tracking). |
| **Measurable** | Recruit at least 3 mock/pilot vendor profiles with real product photos and descriptions; run 5 usability test sessions with target-persona users completing a full purchase flow. |
| **Achievable** | Pilot vendors can be sourced from personal/African student-association networks for the coursework demo; no need for a fully operational supply chain at this stage. |
| **Relevant** | Confirms the core assumption from the validation report — that buyers trust and complete purchases when sizing/vetting/culture-context features are present. |
| **Time-bound** | Vendor onboarding and usability testing completed in the final 2 weeks before submission, using the built MVP. |

**Verdict: Feasible for coursework scope.** Full real-world operations (live logistics, real payments, customs handling) are out of scope for the coursework but are flagged as post-graduation next steps.

## 4. Economic / Financial Feasibility

**Question:** Does the underlying business model make financial sense, and is the coursework build affordable?

| SMART Element | Detail |
|---|---|
| **Specific** | Build the coursework MVP using $0–$50 in costs (free-tier hosting such as Vercel/Render, free-tier database, sandbox payment gateway); model a real-world commission-based revenue plan (15–20% per sale) for the business case section of the report. |
| **Measurable** | Coursework build cost stays under an agreed budget ceiling (e.g., $50); the business-case financial model projects break-even vendor/order volume (e.g., number of monthly orders needed to cover a hypothetical $500/month operating cost at 18% average commission). |
| **Achievable** | Free-tier developer tools fully cover coursework needs; the commission model mirrors proven competitors (Afrikrea, Fashtracker) already operating profitably at similar margins. |
| **Relevant** | Demonstrates understanding of e-commerce monetization, not just technical build — a key coursework evaluation criterion. |
| **Time-bound** | Financial model and cost breakdown completed alongside the written report, due at final submission. |

**Verdict: Feasible.** Coursework build cost is near-zero; the underlying commission-based business model is proven by comparable platforms in the market.

## 5. Legal & Regulatory Feasibility

**Question:** Are there legal/compliance issues that would block the concept, even at prototype stage?

| SMART Element | Detail |
|---|---|
| **Specific** | Identify and document the minimum compliance requirements for a real-world launch: data protection (e.g., GDPR for EU/UK buyers), consumer protection/returns policy, and cross-border customs/import duty disclosure for shipped goods. |
| **Measurable** | Feasibility report includes a compliance checklist covering at least: privacy policy, terms of service, returns/refund policy, and a customs-duty disclaimer — even if not legally binding at coursework stage. |
| **Achievable** | These are standard, well-documented e-commerce compliance templates; no specialized legal counsel is required to draft a coursework-level compliance section. |
| **Relevant** | Shows awareness that a real launch (beyond the coursework demo) requires legal groundwork — relevant to a "software engineer" framing of the exercise. |
| **Time-bound** | Compliance checklist drafted and included in the final report appendix. |

**Verdict: Feasible with caveats.** No blocking legal issue exists for a coursework prototype; real-world launch would require formal legal review (business registration, international tax/duty handling) beyond course scope.

|---|---|
| Technical | ✅ Feasible |
| Operational | ✅ Feasible (pilot scope) |
